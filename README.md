# doctj

Тренажёр клинического приёма для студентов-медиков. Студент открывает
симуляцию, получает виртуального пациента, разговаривает с ним, собирает
анамнез, назначает анализы и ставит диагноз. Система смотрит не только на
итоговый диагноз, но и на то, как студент к нему шёл: что спросил, что
пропустил, что назначил зря.

Зачем это: живых пациентов на всех студентов не хватает, а отрабатывать
расспрос и логику диагноза где-то надо.

Архитектура и принятые решения лежат в Obsidian-vault, `Projects/doctj/` —
семь ADR (0001–0007). README описывает только репозиторий.

## Что где лежит

```
schemas/      JSON-схемы кейса, справочника, профиля-личности + примеры
services/     сервисы (ADR 0006)
  gateway/      Traefik: точка входа и маршрутизация
  identity/     пользователи, роли, токены
  content/      кейсы, справочник, профили-личности; бэкенд редактора кейсов
  simulation/   сессия, виртуальные часы, граф динамики, оркестрация диалога
  patient-llm/  отыгрыш роли пациента
  evaluation/   оценка после сессии
  llm-gateway/  единый доступ к LLM: промпт-кэш, RAG по гайдлайнам
infra/        init-скрипты инфраструктуры (Postgres)
docker-compose.yml
```

Каждый Python-сервис самодостаточен: `app/`, `requirements.txt`, `Dockerfile`.
БД у каждого сервиса своя — физически это один контейнер Postgres с отдельной
базой на сервис.

## Запуск локально

```bash
cp .env.example .env
docker compose up --build
```

- API через Gateway — http://localhost/api/...
- Дашборд Traefik — http://localhost:8080
- RabbitMQ management — http://localhost:15672

Жив ли сервис, проверяет `GET /health`.

## Где сейчас проект

Это скелет. Сервисы поднимаются и отвечают на `/health`, но доменные
эндпоинты пока возвращают `501 Not Implemented`. Дальше — MVP: симуляция
одного визита от начала до оценки.
